### Selection Highlight Color Specification

The **goldRush (#F4B142)** color is used as the selection indicator in both themes. This leverages the existing `colorScheme.secondary` (light) / `colorScheme.primary` (dark) — both resolve to goldRush.

| Selection Token | Light Theme Value | Dark Theme Value | Resolved Via |
|-----------------|-------------------|------------------|--------------|
| Selection border color | `#F4B142` | `#F4B142` | `Theme.of(context).colorScheme.secondary` (light) / `Theme.of(context).colorScheme.primary` (dark) |
| Selection background tint | `#F4B142` at 15% opacity | `#F4B142` at 15% opacity | `AppColors.goldRush.withValues(alpha: 0.15)` |

**Rationale:** goldRush is the existing accent/secondary color in the design system. Using it for selection creates visual consistency — it already represents "interactive emphasis" in the existing theme (button fills in dark mode, secondary actions in light mode). It contrasts strongly against both the blue filled buttons and the white/black surfaces.

Accent reserved for: **Selected player highlight border and background tint only** (in this phase). No other new accent usages introduced.

## Selection Visual Contract

This is the core deliverable for Phase 2. Defines exactly how a selected player looks.

### States

| State | Visual Treatment | Trigger |
|-------|------------------|---------|
| **Unselected (default)** | Existing appearance — filled button (court) or filled button (inactive) with `ShadedContainer` shadow and `Badge` | No player is selected, or a different player is selected |
| **Selected** | GoldRush border (3px) + goldRush background tint (15% opacity) + existing shadow retained | User taps an unselected player (SEL-01, SEL-02) |
| **Deselect → Unselected** | Return to default appearance | User taps the selected player again (SEL-03) or taps a non-target area (SEL-04) |

### Selected State — Detailed Specification

```
┌─────────────────────────────────────────┐
│  3px solid goldRush (#F4B142) border    │
│  ┌───────────────────────────────────┐  │
│  │  Background: goldRush at 15% α   │  │
│  │                                   │  │
│  │   PLAYER NAME (ELO)              │  │
│  │                                   │  │
│  └───────────────────────────────────┘  │
│  Badge (match count) — unchanged        │
│  ShadedContainer shadow — unchanged     │
└─────────────────────────────────────────┘
```

**Implementation approach:** Wrap or modify the existing `ClickablePlayerComponent` to accept an `isSelected` parameter. When `isSelected == true`:

1. **Border:** Apply `Border.all(color: goldRush, width: 3)` around the player widget, outside the existing `Button` border. Use the `ShadedContainer.borderColor` parameter set to `AppColors.goldRush` to achieve this — the existing `ShadedContainer` already supports a `borderColor` override.
2. **Background tint:** Set `ShadedContainer.backgroundColor` to `AppColors.goldRush.withValues(alpha: 0.15)` (blended with surface) — or layer a `ColoredBox` with `AppColors.goldRush.withValues(alpha: 0.15)` behind the button content.
3. **No scale change** for selection (reserve scale for drag-hover at 1.2x — avoid visual collision).
4. **No animation** for Phase 2 selection toggle. Instant visual change on tap.

### Interaction with Existing Visual States

| Existing State | Combined with Selected? | Visual Result |
|----------------|------------------------|---------------|
| Valid drag hover (1.2x scale) | No — drag operations clear selection or selection is ignored during drag | Not applicable |
| Invalid drag hover (disabled, greyed) | No — drag states take priority over selection state | Not applicable |
| Dragging feedback (`_DraggingPlayerComponent`) | No — the dragged player should not show selection highlight in its feedback widget | Not applicable |
| Badge (match count, green/orange/red) | Yes — Badge remains visible and unchanged on the selected player | Badge layered on top of selection highlight |

### Tap Target Specification

| Area | Tap Behavior | Widget Responsible |
|------|-------------|-------------------|
| Player button (on court) | Select this player / deselect if already selected | `DraggablePlayerComponent` → `ClickablePlayerComponent.onTap` |
| Player button (inactive list) | Select this player / deselect if already selected | `DraggablePlayerComponent` → `ClickablePlayerComponent.onTap` |
| Court background (image area, not a player) | Clear current selection (SEL-04) | `CourtComponent` — `GestureDetector` on court `Stack` |
| Scaffold body (padding, gaps) | Clear current selection (SEL-04) | `GameMakerPage` body — `GestureDetector` wrapper |
| AppBar, bottom bar, drawer | No selection effect — ignore | Not wired to selection |
| Search bar (inactive panel) | No selection effect — normal search behavior | `SearchBar` — not wired to selection |

### Single-Selection Invariant

At most **one** player can be selected at any time. Selecting a new player automatically deselects the previous one. Multi-select is explicitly out of scope (per REQUIREMENTS.md).

## Copywriting Contract

Phase 2 introduces **no new UI copy**. Selection is a purely visual state with no text, labels, or messages.

| Element | Copy | Rationale |
|---------|------|-----------|
| Primary CTA | Not applicable | No new buttons or CTAs — selection is triggered by tapping existing player widgets |
| Empty state heading | Not applicable | Selection is an interaction state, not a data state — no "empty" concept |
| Empty state body | Not applicable | See above |
| Error state | Not applicable | Selection cannot fail — tap always toggles selection state |
| Destructive confirmation | Not applicable | No destructive actions in selection |

**Accessibility note:** The selected player should update its `Semantics` to include a "selected" label for screen readers. Suggested semantic: `Semantics(selected: true, child: ...)` wrapping the player widget when `isSelected == true`.
